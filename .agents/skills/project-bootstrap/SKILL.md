# Project Bootstrap

Read [SCHEMA](../../../SCHEMA.md) first; it governs promotion, provenance, navigation, and logging.

## Procedure

1. Start at the wiki index and inspect only relevant project, decision, and source context. Check names, aliases, and objectives for an existing initiative before creating anything.
2. Establish the supported objective, stage, constraints, open questions, next action, and evidence links. Label unknowns and user-provided decisions; do not infer commitments from source material.
3. Resolve blocking ambiguity one decision at a time, using [grill-me](../grill-me/SKILL.md) when useful. Do not create a project for an unconfirmed possibility.
4. Apply the canonical knowledge-promotion rule. Keep tentative framing transient; otherwise update an existing project or create only the minimum useful page under `wiki/projects/`.
5. For durable changes, follow canonical QUERY for user-decided state and INGEST for new sources, including index/overview maintenance and logging. Reuse unchanged state on reruns.

## Boundaries

- **Side effects:** a transient framing or minimal durable project state with associated navigation/log updates; no scaffolding unrelated to the next action.
- **Approval:** confirm unresolved commitments before recording them; ask before external actions, destructive changes, or raw-source changes as required by SCHEMA. Framing is not permission to execute the project.
- No duplicate projects, speculative decisions, fabricated owners/deadlines, or placeholder facts.
